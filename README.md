# wucongkai 的个人主页

一个适合部署到 `https://wucongkai.github.io/` 的个人 Wiki。
参考 jyywiki.cn 的阅读体验：简洁导航、纸张式正文、手写英文字体和蓝紫色链接。
页面代码与示例文章独立编写，没有复制原站文章、图片或个人信息。

## 实现方式

```text
site.config.ts              → 姓名、简介、项目、联系方式
content/posts/*.mdx         → 每一篇文章，构建时自动生成列表和页面
app/globals.css             → 页面配色、字号、宽度、留白
Next.js + MDX              → 生成 out/ 中的静态网站
GitHub Actions             → 每次推送 main 后自动构建
GitHub Pages               → 发布到 wucongkai.github.io
```

使用 Next.js App Router、MDX、普通 CSS。这个规模的页面用集中式 CSS 就可以保持一致的排版，不需要再引入组件库。所有英文字体随网站一起发布，访问时无需连接 Google Fonts。

## 1. 在本地运行

安装 Node.js 24 LTS。若已经使用 nvm，可执行 `nvm install` 和 `nvm use`，版本由 `.nvmrc` 指定。

在这个目录打开终端：

```bash
npm ci
npm run dev
```

打开终端显示的本地地址，通常是 `http://localhost:3000`。修改文件并保存后，页面会自动更新。

## 2. 用本地网页写文章（推荐）

不需要手工编辑 MDX 文件或逐次执行 Git 命令。在项目目录运行：

```bash
npm run editor
```

打开 **http://127.0.0.1:4311**。默认只监听本机，终端保持开启即可；按 `Ctrl+C` 关闭。需要 Node.js 22 或更高版本，已有 nvm 环境可以先运行 `nvm use 22` 或 `nvm use 24`。

1. 从左侧选择文章，或点击「新建文章」。
2. 填写标题、日期、分类、摘要和正文。新文章的网址支持小写英文、数字和连字符，首次保存后固定。
3. 右侧预览与网站使用同一个 MDX 渲染器和样式，支持代码高亮、表格、引用与折叠内容。窄屏下预览显示在正文下方。
4. 「保存到本地」只更新当前文章文件，`⌘/Ctrl + S` 也可以保存。新文章此时为草稿，不生成公开页面。
5. 「保存并发布」将当前文章设为公开，自动保存、检查远程更新、构建待发布版本、提交当前文章并推送到 `origin/main`。GitHub Actions 随后自动部署，可以在页面查看日志并跳转到部署进度。
6. 选择已保存的文章，点击「删除文章」并确认，即可删除文章。如果有未保存的编辑，请先保存或放弃这些修改。

文章列表中每篇文章下方都有「上移 / 下移」。点击后顺序自动保存到本机的 `content/post-order.json`，刷新或换设备后仍保留；文章日期、正文和正在编辑的内容保持原样。调整好后点击列表下方的「发布排序」，构建、提交并推送首页顺序。文章正文的「保存并发布」与「发布排序」各自处理对应内容。

未设置顺序时按日期由新到旧排列。首次移动后按自定义顺序显示；新增且尚未排序的文章出现在最前面，已删除文章会自动忽略。搜索时需先清空搜索再排序，避免移动到未显示的文章前后。第一篇不能上移，最后一篇不能下移；多人同时调整时会检查版本，旧列表需要刷新后重新操作。

发布排序只提交排序数据；首次发布时还会为已部署的网站接入必要的排序读取代码，不带入其他本地代码修改、暂存内容或未提交的草稿。构建失败不提交，推送失败保留本地顺序，可以点击「发布排序」重试。尚未提交的文章不会随排序发布，之后发布新文章并调整位置时，再发布一次排序即可。

删除会先检查远程状态并构建删除后的版本，再只提交当前文章的删除、推送到 GitHub；推送成功后才移除本地文件。部署完成后，线上文章从列表中移除，原文章地址将返回未找到。构建或推送失败时，本地文件仍可打开；再次点击「删除文章」可重试，同一删除不会重复创建提交。未提交到仓库的本地草稿不需要重新构建、提交或推送，但仍会先联网核对远程状态。

删除前的完整文章会备份到项目的 `.editor-trash/`，具体路径显示在操作结果和日志中；该目录已经加入 `.gitignore`，不会推送到 GitHub。需要恢复时，将对应备份复制回 `content/posts/原文章网址.mdx`，再在编辑器中打开并发布。已提交的文章也可以从 Git 历史恢复。删除不移除图片，避免影响其他文章。若其他程序在删除过程中更新了本地文章，新内容会保留并显示提示。

编辑中的内容会自动暂存到当前浏览器，重新打开文章可以恢复。浏览器暂存不等于保存到文件；清除浏览器数据也会清除暂存。其他窗口或编辑器修改同一篇文章时，会阻止旧版本覆盖，提示先保留内容、重新载入。

发布沿用本机现有的 Git 登录方式，不在页面填写或保存 GitHub 令牌。首次使用请确保已设置 Git 作者信息，并且本机能够正常向此仓库推送。远程有更新、当前不是 `main` 分支，或存在其他未推送提交时，页面会给出处理提示，不会自动强制覆盖。

发布前在临时目录构建「当前提交 + 当前文章」，只提交并推送这篇文章。其他草稿、代码修改和暂存区内容会保留。构建失败不会创建提交；推送失败保留已保存的文章与提交，修复网络或登录后可重试，不会重复创建相同提交。编辑器显示「已推送」并不代表 Pages 已完成部署，以 Actions 结果为准。

图片沿用 `public/images/` 的使用方式。编辑器可插入图片引用并预览本地图片；**新图片需要先提交到仓库**，单篇文章发布不会顺带提交其他文件。

### 编辑项目与关于我

写作台顶部可以切换「文章 / 笔记」「项目」「关于我」。

- **项目**：添加项目，修改名称、简介、链接和状态，使用「上移 / 下移」调整首页顺序。「移除」后在保存前可以撤销，也可以清空项目列表。链接支持 `http(s)` 地址、以 `/` 开头的站内路径或 `#` 锚点。
- **关于我**：修改姓名 / 昵称、网站标题、网站摘要、个人介绍、GitHub 主页和联系邮箱。个人介绍使用纯文本，空一行分段；邮箱留空后首页隐藏邮箱。
- 右侧显示使用首页样式的预览；窄屏下预览位于表单下方。浏览器暂存、版本冲突检查和 `⌘/Ctrl + S` 同样可用。
- 「保存到本地」更新 `site.config.ts` 中当前部分的字段。「保存并发布」只把当前部分合入已提交的网站版本，构建通过后提交并推送。另一部分的未发布编辑、文章草稿、其他文件以及暂存区中的其他修改会保留，即使它们也在 `site.config.ts` 中。

配置文件仍是内容来源，无需迁移现有资料。编辑器安全读取普通对象和文本，不执行配置代码；若手动改成动态表达式、展开运算或函数，需先恢复成明确的文本字段。网站正式地址 `url` 仍需在文件中修改。构建失败不提交；推送失败保留内容与提交，可在对应部分再次发布。

如果端口被其他程序占用：

```bash
EDITOR_PORT=4312 npm run editor
```

### 同一局域网内访问

先用 `Ctrl+C` 停止已经运行的编辑器，再启动局域网模式：

```bash
nvm use 22
npm run editor:lan
```

终端会显示所有可访问的 IPv4 地址及随机访问口令。以电脑地址 `10.31.112.198` 为例，其他机器打开 **http://10.31.112.198:4311**，输入终端里的口令即可编辑。运行编辑器的电脑需要保持开机、终端运行，访问设备需要在可互通的局域网中。

局域网模式监听 `0.0.0.0`，本机仍可使用 `http://127.0.0.1:4311`，也需要登录。口令不写入项目或网址，重启默认生成新口令；登录有效期为 12 小时，重启或退出登录后失效。共享口令的人拥有文章、项目和个人介绍的编辑与发布权限；文件与 Git 推送由运行编辑器的电脑处理。多个设备同时修改同一内容时仍会检查版本，避免互相覆盖。

如需只监听某个网卡，使用 `EDITOR_HOST=10.31.112.198 npm run editor`。也可通过环境变量 `EDITOR_PASSWORD` 配置至少 12 个字符的口令；不要把口令提交到 Git。恢复仅本机访问时，停止服务并运行 `npm run editor`，同时取消自定义的 `EDITOR_HOST` 环境变量。

使用普通 HTTP，只适合可信局域网，不要通过路由器端口映射暴露到公网。若其他机器无法连接，检查 IP 是否变化、macOS 防火墙是否允许 Node.js 的传入连接，以及 Wi-Fi 是否启用了访客网络或设备隔离；不需要关闭整个防火墙。

编辑器源码位于 `editor/`，不会进入静态导出的 `out/`，线上网站不包含管理接口。验证命令：

```bash
npm run test:editor
npm run typecheck
npm run build
```

## 3. 替换个人资料

推荐在写作台的「关于我」和「项目」中编辑，也可以直接编辑 `site.config.ts`：

- `name`、`title`：姓名和网站标题。
- `bio`：个人介绍，数组中每一项是一段文字。
- `projects`：项目名称、简介、链接和简短状态。
- `github`：GitHub 主页地址。
- `email`：可公开的联系邮箱；留空就不显示。
- `url`：网站正式地址，当前为 `https://wucongkai.github.io`。

项目和文章都使用你填写的内容。首页的当前个人介绍是一段可直接替换的中性占位文字，没有虚构职业、学历、成果或项目经历。

## 4. 直接编辑文章文件（可选）

在 `content/posts/` 下新建一个 `.mdx` 文件，例如 `my-first-note.mdx`：

```md
---
title: "我的第一篇笔记"
date: "2026-09-13"
description: "用一两句话说明这篇笔记讲什么。"
category: "学习笔记"
draft: false
---

这里开始写正文。

## 一个小标题

- 支持列表和链接。
- 支持代码块、引用、表格。
```

文件名使用小写英文字母、数字和连字符；它就是文章网址的一部分：`/notes/my-first-note/`。
首页默认按日期由新到旧列出文章；在写作台调整顺序后，使用 `content/post-order.json` 中的顺序。无需手工修改导航。文章标题由模板显示，正文直接从二级标题开始即可。
设置 `draft: true` 后，该文章不会出现在列表中，也不会生成公开页面。
删除所有文章时，首页会显示空状态，构建仍然可以完成。

图片放入 `public/images/`，在文章中写 `![图片说明](/images/example.png)`。
文章内链写成 `/notes/文章文件名/`，不要直接链接 `.mdx` 源文件。

## 5. 部署到 GitHub Pages

### 创建仓库

登录 GitHub，创建公开仓库 **`wucongkai.github.io`**。这是个人主页仓库的固定命名方式。
如果已有同名仓库，先检查里面的内容，不要覆盖已有网站。

将项目源文件提交到仓库的 `main` 分支，必须包含 `package-lock.json` 和 `.github/workflows/deploy.yml`。
不要上传 `node_modules`、`.next` 或 `out`；它们已在 `.gitignore` 中排除。

如果从新下载的项目开始且还没有 Git 仓库，可执行：

```bash
git init -b main
git add .
git commit -m "Create personal homepage"
git remote add origin https://github.com/wucongkai/wucongkai.github.io.git
git push -u origin main
```

如果当前目录已有 Git 仓库，跳过 `git init`；如果已有 `origin`，先用 `git remote -v` 核对地址。GitHub 推送需使用你自己的正常登录方式，不要把密码或令牌写入项目文件。

### 开启 Pages

1. 打开仓库的 **Settings → Pages**。
2. 在 **Build and deployment → Source** 选择 **GitHub Actions**。
3. 打开仓库的 **Actions → Deploy personal homepage**。
4. 如果第一次推送发生在启用 Pages 之前，点击 **Run workflow** 重新运行。
5. `build` 和 `deploy` 都完成后，访问 **https://wucongkai.github.io/**。

以后每次向 `main` 推送修改，都会自动重新发布。Actions 页面会显示失败原因和日志。

## 6. 本地检查正式构建

```bash
npm run build
```

Next.js 会检查 TypeScript，并把首页、文章页、404 页面、字体等输出到 `out/`。
`out/` 可以由任何静态 HTTP 服务器提供访问；不要通过双击 HTML 文件来检查网站。

## 配置要点

- `output: 'export'`：输出静态文件；GitHub Pages 不需要也不运行 Node.js 应用服务器。
- `trailingSlash: true`：文章输出为 `/notes/slug/index.html`，便于直接打开子页面。
- `images.unoptimized: true`：不依赖服务器端图片优化。
- 当前以 `wucongkai.github.io` 根路径部署，无需 `basePath`。如果改成普通项目仓库或自定义域名下的子路径，需要相应调整配置与资源链接。
- 线上页面使用静态文件和普通联系链接；本地写作台单独运行，不依赖线上后台或数据库。
